# ECU書き込みサイクル判定システム

**バージョン**: 1.0.1  
**最終更新**: 2026-09-29

## 1. システム概要
本システムは、2台のカメラを活用して作業サイクルの正否をリアルタイムに自動判定・記録する品質保証検査システムです。
- **USB物理ポート永続固定 (Linux `by-path` 対応)**:
  - 起動時やUSB抜き差し時にカメラデバイス番号（`/dev/video*`）が入れ替わる問題を防ぐため、USBポートの物理配線パス（`/dev/v4l/by-path/`）による永続固定化と動的逆引き解決に対応。
  - 既存設定に対する起動時自動マイグレーション機能を搭載。
- **カメラ1（QRカメラ）**:
  - 作業指示プロジェクション準拠の多段階画像補正（CLAHE・二値化・拡大・ガンマ補正・パディング等）とフォールバック（pyzbar / WeChatQRCode / OpenCV）を備えた高耐性QRリーダー。
  - 指定ROI内のQRコードを検出し、直近10回の履歴に含まれない「新規QRコード」が提示された瞬間にサイクルを自動スタート。
  - QRコード文字列の先頭4桁から「正解コミット番号」を取得。
  - 作業中のQRコード消失（持ち出し）を常時監視。瞬間的な未読（手ブレ等）は除外し、設定フレーム数以上継続した場合のみ異常判定します。
- **カメラ2（画面・コミットカメラ）**:
  - 04P_commit_verify 準拠のOCRエンジンにより、指定ROIから4桁数字のコミット番号を読み取り、正解コミット番号と照合。
  - 指定ROIエリアの画面色（緑・黄・赤）をHSV解析により常時検出。設定画面から色閾値を動的に調整可能。
- **サイクル判定ステートマシン**:
  - 正常シーケンス: [待機/緑] -> [作業/黄] -> [完了/緑] へ復帰し、コミット番号一致でOK判定。
  - 異常判定 (NG): 途中で赤色検知、黄色中の未完了QR持ち出し、コミット番号不一致で即時NG判定。
- **UI & メンテナンス機能**:
  - inspection_app に完全準拠したダークグレーテーマGUI。
  - NG履歴リストの操作性向上（ダブルクリックまたはEnterキーでの詳細情報確認、クリック位置フォールバック保護）。
  - ラズパイ本体日時設定（SystemDateTimeDialog）およびワンクリック起動スクリプト自動生成機能を搭載。
  - ディスク負荷軽減のため画像保存は行わず、CSV判定ログおよびアプリログのみを保存。

## 3. 画面レイアウトと操作手順

```
┌──────────────────────────────────────────────────────────────────────────────────┐
│ HEADER (高さ80px):                                                               │
│   [ステータス大表示 (待機中/作業中/OK/NG)]          [？ヘルプ] [時計 YYYY/MM/DD]  │
├──────────────────────────────────────────────────────┬───────────────────────────┤
│                                                      │ 操作パネル (固定幅 420px) │
│  カメラプレビューエリア (Card)                        │                           │
│  ┌────────────────────────┬────────────────────────┐ │ 1. コミット番号 (超特大)   │
│  │ カメラ1: QRコード      │ カメラ2: 画面色・OCR   │ │    [ 0001 ]               │
│  │ ┌────────────────────┐ │ ┌────────────────────┐ │ │                           │
│  │ │                    │ │ │                    │ │ │ 2. サイクル状態           │
│  │ │  [QR ROI枠]        │ │ │  [コミットROI枠]   │ │ │    [待機] -> [作業] ->[完了│
│  │ │                    │ │ │  [画面色ROI枠]     │ │ │                           │
│  │ └────────────────────┘ │ └────────────────────┘ │ │ 3. NG履歴 (ダークListbox)  │
│  │ QR: ABCD...          │ OCR: 0001  色: 緑    │ │    [20:30] #1234 持ち出し │
│  └────────────────────────┴────────────────────────┘ │                           │
│                                                      │ 4. 操作ボタン群 (下部固定) │
│                                                      │    [履歴リセット][結果フォルダ
│                                                      │    [ ブザー停止 (赤色) ]  │
│                                                      │    [ 詳細設定 (深緑色) ]  │
└──────────────────────────────────────────────────────┴───────────────────────────┘
```

### 操作手順
1. アプリを起動します（`python main.py` またはデスクトップの起動スクリプト）。
2. カメラ1の赤枠（QR読取ROI）内にワークのQRコードを提示します。
3. 過去10回と異なる新規QRコードが認識されると、先頭4桁のコミット番号が抽出されサイクルが自動開始します。
4. オペレーターが作業を開始すると、カメラ2の指定エリアの画面色が黄色に変化し、「作業中」状態へ移行します。
5. 作業が完了し画面色が再び緑色に戻ると、コミット番号の照合が行われ、一致していれば「OK」が出力されます。
6. 途中で赤色の画面色になった場合、黄色のままQRコードが持ち出された場合、またはコミット番号が不一致の場合は「NG」となり、ブザー・ログ記録・NG履歴追加が行われます。

### キーボードショートカット
- `Space` / `B` / `b`: ブザー停止 / 待機復帰
- `S` / `s`: 詳細設定画面を開く
- `F11`: フルスクリーン / 通常ウィンドウ切り替え
- `Escape`: ダイアログを閉じる

## 4. 設定ダイアログのタブ構成
キーボードの `S` キーまたは操作パネルの「詳細設定」ボタンから起動します。

| タブ | 名称 | 設定内容 |
|---|---|---|
| 1 | カメラ設定 | カメラ1 / カメラ2のデバイス選択プルダウン、解像度、FPS、接続再スキャン |
| 2 | 読取・ROI設定 | カメラ1 QRコードROI、カメラ2 コミット番号ROI、カメラ2 画面色ROIのマウスドラッグ指定、座標表示 |
| 3 | 色判定・サイクル設定 | 緑・黄・赤のHSV閾値スピンボックス、QR消失判定許容フレーム数（瞬間未読除外） |
| 4 | 画素数設定 | 撮影解像度、プレビュー解像度の選択 |
| 5 | システム設定 | Tesseract-OCRパス検証、デスクトップ起動スクリプト作成、ラズパイ本体日時設定（SystemDateTimeDialog） |

## 6. テストの実行

自動単体テスト（QR・OCR前処理・画面色HSV判定・サイクルステートマシン各シナリオ）を実行する場合：

```bash
python -m unittest tests/test_all.py
```

GUIを表示せずテストモードで起動確認を行う場合：

```bash
python main.py --test
```
